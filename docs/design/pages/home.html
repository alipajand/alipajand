How I work

Frontend architecture is still where I'm strongest. What changed is that I can follow a feature past the browser when the product needs it.— Ali Pajand

I started out doing frontend work and kept going deeper into the hard parts of it: component architecture, design systems, accessibility, and keeping dense interfaces fast on the devices people actually use.

The scope widened from there. Owning an interface properly means owning what it depends on, so I took on API contracts, data models, testing strategy, CI, and the async workflows sitting behind the screens. LedgerGuard is the clearest version of that: I built the product, the API, the schema, and the queue-backed document pipeline myself.

Frontend architecture is still where I'm strongest. What changed is that I can follow a feature past the browser when the product needs it.

Technical leadership, for me, is mostly unglamorous work: making the architecture explainable in design docs before it gets expensive, mentoring engineers on the patterns, cutting accidental complexity, turning one-off patterns into shared ones, reviewing the decisions that are expensive to reverse, and still writing production code.

Tooling & open source

Repository audits across CLIs, CI, MCP, and editor skills and plugins. The audit engines use deterministic rules; host clients have their own data handling.

agent-context-doctor

Sep 2026

Audits agent instruction files and committed Claude Code and MCP settings for quality and safety problems.

  • Flags placeholders, contradictions, stale commands, broken references, pasted secrets, and hidden Unicode
  • Catches risky agent settings such as bypassPermissions, hooks that run remote scripts, and unpinned MCP servers
  • Scores the repository from 0 to 100 and reports to the terminal, SARIF, or pull-request annotations
Repository

agent-pr-reviewer-lite

Sep 2026

Deterministic risk pre-screen that flags the files in a pull request that need human review before merge.

  • Flags auth, billing, migrations, CI, secrets, and agent-permission changes from fixed, readable rules
  • Reads added lines for skipped tests, lint suppressions, new dependencies, and auto-run agent commands
  • Names CODEOWNERS from the base branch so a pull request cannot pick its own reviewers
Repository

agent-readiness-kit

Sep 2026

Scores how ready a repository is for AI coding agents across 13 categories, from 0 to 100.

  • Checks instruction files, architecture docs, scripts, tests, and safety boundaries
  • Scaffolds starter files for Cursor, Claude Code, Codex, Copilot, and CI with init, generate, and fix
  • Gates CI on a minimum score and writes JSON, JUnit, SARIF, Markdown, or HTML reports
Repository

agent-readiness-action

Oct 2026 · v1.2.0

Runs agent-readiness-kit and agent-context-doctor on pull requests; published in the GitHub Actions Marketplace with the v1 tag.

  • Fails below a minimum score or when a pull request lowers the score from the base branch
  • Bundles both engines at pinned commits, so nothing is downloaded from a registry at run time
  • Hardened for untrusted pull requests: no workflow-command injection and no writes through symlinks
