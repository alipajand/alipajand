# 03 · The AlwaysGeeky and Emplifi scenes

Two scenes that test the grammar on projects with very different evidence. AlwaysGeeky has two shipped screenshots and a documented system behind them. Emplifi has no screenshots at all. Each scene uses the shared contract (see 02) and adds only its project's move (see 01).

Every claim in both scenes is read from `data/projects.ts` at build time. The step headings, scene notes, materials notes and drawing labels are new copy and are listed for approval in 01.

## AlwaysGeeky · from the interface to the component system under it

**The move:** the detail callout, in blueprint blue. Blue always means "this part is shared".

**Who is who.** AlwaysGeeky Games makes Voxies. The marketplace and login in this scene are Voxies surfaces. The marketplace closed in July 2026, so both screenshots are labelled historical, the caption says it closed, and neither address is linked. The first card says this in one sentence.

**The idea:** start on the product a reader can see, then go down through it. The marketplace is one of four surfaces. They stand on one library, the library's contract is written in Storybook, and CI enforces it. The transition is a **descent**: the camera follows one blue line from a part of the interface down to the gates.

**What is not shown, on purpose:**

- No Storybook screen. AG-03 is a drawing of what a contract specifies, labelled "Editorial diagram". It is not a picture of Storybook.
- No component inventory. The portfolio does not have a verified list of the library's components, so none is drawn.
- No pipeline vendor, check count or pass rate. AG-03 names the kinds of gate the case study describes and nothing more.

## Emplifi · technique, not magnitude

**The move:** the probe and the reference ruler, in ochre.

**The idea:** there are no Emplifi interface screenshots, so the scene never shows one. It draws the **constraint and the approach**: a chart in an embedded webview, where in the render path the profiling looked, how a module is composed, and how the work was designed to fit a frame. It does not show how much anything improved. No source in the portfolio gives a measured before and after, so P2's before/after timelines and the 80% figure are gone.

**What is not shown, on purpose:**

- No Emplifi interface, logo, metric name, or anything that imitates their product.
- No measured value and no comparative length. 16.7 ms appears only as the length of one frame on a 60 Hz display, called a reference every time.
- **The 80% claim is not shown.** The data file's outcome line and meta description contain it. The build drops any sentence with a percentage from the scene and the case study, and the review checks every page for a percentage figure. This PR does not change production data.

**Sources in `data/projects.ts` (emplifi):** `cardProblem` (first sentence only), `caseStudy.context`, `problem`, `myRole`, `technicalDecisions[0]` and `[1]`, `uxDecisions` (monitoring), and `diagrams` (the compare diagram's caption and its approach column).

## Phone and reduced motion

**Phones (P2.2).** Below 900 px there is no stage (see 02). Each step is heading, text, one figure, and the figure draws in as it arrives. P2.1 put a scaled-down stage window above the cards and a sideways-scrolling copy of the drawing in each card, so a phone showed two versions of every drawing at once and the window's labels were too small to read. Below 768 px each figure is now a **phone sheet**: the same drawing recomposed for a 360-unit column, with every label set at 12 px or more as rendered at 360 px wide (13.4 px at 390). The review measures every label at 360, 390 and 430 px.

The phone sheets keep every fact and material label of the wide drawings; what they drop is repetition (the drawing's own sheet strip, which the HTML strip under each figure already carries) and the wide sheet's frame. Strips stay in HTML under each phone figure, so they wrap rather than shrink. From 768 to 899 px the wide drawing is shown, in a sideways-scrolling frame where it does not fit. The match cut does not run below 900 px; the case study's hero is simply in place.

Under reduced motion, or without script, neither scene moves. Each step shows its static figure: on a phone the phone sheet, otherwise the detail lens as a still crop, the assembly, AG-03, and the four Emplifi drawings. The case study follows. See `screenshots/*-reduced-*`.
