# Technical feasibility and performance risk

Checked against the production app at `b9cdf8d`. Installed versions, read from `node_modules`: Next.js 16.4.2, React 19.3.1, GSAP 3.15.0, Lenis 1.3.26. **Nothing here is implemented in production.** This is an assessment for a decision.

| Piece                                     | In the prototype                                                                | In production                                                                                                                                                                                                                                                                                                                                                                                                                      | Verdict                          |
| ----------------------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |

## Measured cost (lab)

From `capture/perf.mjs`: headless Chromium on an Apple-silicon laptop, local static server (uncompressed HTML, CSS and JS), with fonts and GSAP from their CDNs. These are relative indicators, not field data. Headless frame timing is not a real device's compositor.

| Probe                             | Delivered (KB)                                              | LCP    | CLS   | Frames while scrolling the whole sequence in 8 s |
| --------------------------------- | ----------------------------------------------------------- | ------ | ----- | ------------------------------------------------ |
| Desktop 1440×900                  | 238 total: fonts 87, scripts 56, HTML 38, CSS 34, images 23 | 196 ms | 0.026 | 481 frames, median and p95 16.7 ms, none > 33 ms |
| Desktop, 4× CPU slowdown          | same                                                        | 272 ms | 0.022 | 481 frames, p95 16.8 ms, none > 33 ms            |
| 390×844 viewport, 4× CPU slowdown | same                                                        | 380 ms | 0     | 481 frames, p95 16.8 ms, none > 33 ms            |

What this says: the sequence is cheap in bytes (GSAP and ScrollTrigger are the 56 KB of script, and are already in the production bundle), and the main thread is not the bottleneck: CSS 3D runs on the compositor. What it does not say: how a real mid-range phone's GPU handles five large composited layers. That needs a device test. The small desktop CLS is most likely the web-font swap on the cover; it was not isolated.

## Performance risks

| Risk                                                    | Likelihood | Impact                                                                                     | Mitigation                                                                                                                                                                                         |
| ------------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Compositor load from five 3D layers plus the screenshot | Medium     | Dropped frames during the tilt on low-end Android; the scrub smoothing hides small hitches | Promote layers only while `motion-live`. Drop the floor shadow and sheets 4–5 on narrow screens. Fall back to the static drawing when `navigator.deviceMemory ≤ 2` or after sustained long frames. |
| LCP on the cover                                        | Low        | The LCP element is the name (text). It depends on the display font arriving.               | Preload the one display weight; `font-display: swap` with a metric-matched fallback; keep the screenshot lazy and off the LCP path.                                                                |
| CLS from fonts                                          | Low        | The name is sized in `vw` and `svh`, so a fallback font changes width, not layout height   | `size-adjust` on the fallback (handled by `next/font`)                                                                                                                                             |
| INP                                                     | Low        | The only handlers are a toggle and the demo buttons; there is no scroll-jank handler       | Keep the tone probe rAF-throttled (it already is)                                                                                                                                                  |
| Three font families                                     | Medium     | Extra bytes, and a typography change from Geist                                            | Subset to Latin; use one display weight (900) and two text weights; consider Geist Mono instead of Martian Mono                                                                                    |
| Sequence length                                         | Medium     | About 10 viewports of scroll before the story                                              | Tighten to about 7; the skip link and "Skip intro" already exist                                                                                                                                   |
| Resize and orientation change                           | Low        | The timeline rebuilds on width change, which costs one layout                              | Debounced already (200 ms); height-only changes (the mobile URL bar) are ignored                                                                                                                   |

Production budgets from the owner decisions (LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1, Lighthouse mobile Performance ≥ 90) were **not** measured here. They can only be measured on a production build with `next/font` and `next/image`.
